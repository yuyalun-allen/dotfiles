# 修订指南

## 修订文稿

用户的初始文稿很可能只是为了阐明逻辑，或许存在细节不清晰、表述口语化的问题。

用户提供的可能是中文文稿，如果需要输出英文文稿请自行完成翻译动作。

用户一般会提供一份 markdown 文档作为初始文档，`>` 标记的为注释段落。
用户还有可能提供更多文字作为上下文参考。

输出文档格式需根据上下文确定，可能是 markdown ，也可能是 tex 或 docx 等格式。

## 修订原则

从词语、句式、段落三个层面进行修订。

- **词汇：**检查词汇表述客观性。应该确保表述的客观，避免过度吹捧自身贡献（overclaim），也避免过度贬低他人工作，同时需要保证表述的严谨性，避免口语化。
- **句式：**确保句式正确性。学术表达不要求华丽的修辞，要求表达清晰明了，句式结构正确。
- **段落：**检查段落逻辑连贯性。应该从具备逻辑推理能力和有限领域知识的角度推敲文稿逻辑，指出不匹配的概念、断裂的逻辑、缺失的细节。

当不确定表意时，应使用 `[]` 进行行内注释，说明原因并提供备选。

应输出一份完整的修订后文件，将原有的文件移动到 <name>-draft.<ext>，输出新的完整的文件到 <name>.<ext>。
